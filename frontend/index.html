🏛️ Open Banking Security Pipeline Architecture
Dummy Data Only

This simulator demonstrates the security controls required when fintech applications access customer bank data under Open Banking regulations (such as UK Open Banking / PSD2 / FDX). It implements defense-in-depth across authentication, delegated user authorization, data minimization, and replay prevention.

1. Identity

Fintech Partner

Issues hashed API key (ob_live_...). Enforces partner identification & sliding window rate limits.

2. Delegated Auth

OAuth 2.0 + PKCE

Authorization Code + S256 PKCE with explicit customer consent screen. Never treats API key as user consent.

3. Cryptography

RS256 JWT & JWKS

Asymmetric RSA 2048-bit signing. Zero-DB token verification using cached public key from JWKS.

4. Resource Server

OWASP Protections

BOLA (API1) object validation, Data Minimization (API3), Scope RBAC (API5), and DPoP Replay defense.

5. Compliance

Sanitized Audit

Structured audit log recording auth failures, consent decisions, and attacks without leaking secrets.

⚡ OWASP API Security Top 5 Attack Simulator

Demonstrate how each OWASP API Security vulnerability is tested and blocked by our security architecture. Click any attack button below to simulate an active exploit attempt against the local backend.

API1: BOLA / IDOR
Cross-Customer Account Tampering
Alice's token attempts to query Bob's private checking account (acc_bob_chk_01). The server verifies that Alice does not own or have active consent for Bob's account and returns safe 404/403.
API2: Broken Authentication
Tampered RS256 JWT Signature
An adversary alters cryptographic signature bits in transit. The server validates RS256 using the local cached public key and instantly rejects the request with HTTP 401.
API3: Excessive Data Exposure
Internal Banking Property Filtering
Validates that internal bank routing codes (internal_routing_code) and core ledger references (internal_ledger_ref) are never leaked in API response payloads.
API4: Unrestricted Consumption
Partner Rate Limit Burst (DoS)
Sends a rapid burst of requests. The sliding window rate limiter detects threshold exhaustion, returns HTTP 429 Too Many Requests, and sets Retry-After headers.
API5: Function Level Auth
Privilege Escalation on Payments API
Attempts to initiate a financial transfer using an access token that only has read-only scopes. The server enforces RBAC and blocks the execution with HTTP 403 Forbidden.
Replay Defense: DPoP Cache
Proof-of-Possession Token Replay
An intercepted DPoP proof header is replayed a second time. The anti-replay sliding cache detects duplicate proof JTI and blocks the second request with HTTP 401 Replay Detected!
